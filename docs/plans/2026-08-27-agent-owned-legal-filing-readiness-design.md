# تصميم جاهزية الدعوى واعتماد الوكيل

## القرار

تُفصل جاهزية تجهيز الدعوى عن اعتمادها النهائي. يرى المستخدم الملف «جاهزاً لبدء إجراءات الرفع» متى اكتملت البيانات والمستندات وحقول تقاضي، ولا يُطلب منه اعتماد الملف أو لقطة المذكرة.

عند بدء الرفع ينشئ النظام مهمة تقاضي بالحافظة الحالية. يطابق وكيل تقاضي شاشة المراجعة النهائية مع الحزمة (الأطراف، عنوان الدعوى، قيمة المطالبة والمستندات)، ثم يسجل اعتماد الوكيل تدقيقياً ويكمل الإرسال. أي اختلاف أو نقص يوقف المهمة قبل الاعتماد وينشئ مهمة مراجعة مرتبطة بها.

## تدفق البيانات

1. تولد صفحة التجهيز المستندات وتثبت لقطة مسودة حديثة تلقائياً.
2. تحسب الواجهة `canStartFiling` من اكتمال البيانات والحافظة فقط، وتعرض حالة مراجعة الوكيل بصورة مستقلة.
3. يضغط المستخدم «بدء إجراءات رفع الدعوى» مرة واحدة؛ لا يوجد زر اعتماد قانوني للمستخدم.
4. يراجع الوكيل البيانات في بوابة تقاضي. بعد نجاح المطابقة يستدعي إجراء قاعدة بيانات لا يقبل إلا `service_role` ويسجل مصدر الاعتماد `taqadi_agent` وهوية العامل والمهمة.
5. يكمل الوكيل الاعتماد في تقاضي. تبقى حراسة الانتقال إلى `filed` كما هي ولا تسمح بالانتقال قبل وجود لقطة معتمدة وحديثة.

## ضوابط الأمان

- لا يستطيع المتصفح استدعاء اعتماد الوكيل.
- لا يتم اعتماد مسودة إلا إذا كانت المهمة مقفلة للعامل نفسه وفي مرحلة المراجعة النهائية، وكانت الحزمة كاملة ومطابقة للقضية والعقد والقيمة الحالية.
- يسجل التدقيق رقم المهمة والعامل ونتيجة المطابقة ووقت الاعتماد.
- يظل التحقق البشري مطلوباً فقط عند CAPTCHA أو تعارض أو فشل غير محسوم، وليس كخطوة روتينية.

## واجهة المستخدم

- «جاهز لبدء إجراءات الرفع» تعني أن الصفحة مكتملة ويمكن إنشاء المهمة.
- «مراجعة الوكيل» تظهر كحالة: لم تبدأ، قيد المراجعة، معتمدة، أو تحتاج تدخلاً.
- لا تظهر للمستخدم رسائل «الملف القانوني لم يعتمد» أو «اعتماد الملف الآن» كعوائق قبل بدء الإجراءات.
