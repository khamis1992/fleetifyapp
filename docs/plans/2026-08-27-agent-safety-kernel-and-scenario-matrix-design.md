# تصميم نواة أمان الوكلاء ومصفوفة السيناريوهات

**التاريخ:** 27 أغسطس 2026
**النطاق:** وكلاء Fleetify المجدولون، المراجعون عند الطلب، تدقيق النظام، التكاملات الخارجية، ووكيل تقاضي.

## النتيجة التنفيذية

سبب حادثة عقد ألياس ليس خطأ OCR منفرداً. المسار البرمجي كان يطلب وجود حقل `signed_contract` لإكمال الجاهزية، ثم عوّض النقص بملف من عقد سابق يشارك اللوحة. أي أنه حسّن **اكتمال الحقول** على حساب **صحة الدليل**، واستخدم اللوحة كمفتاح ضعيف، ونفّذ بهوية حساب المستخدم، واستمر عند الغموض بدلاً من التوقف.

قاعدة النظام بعد هذا التصميم:

> لا تنفيذ تلقائياً إلا إذا كانت الهوية، ملكية الكيان، مصدر الحقيقة، الثقة، وعدم التعارض كلها مثبتة. النقص يفتح طلباً منظماً؛ ولا يسمح باختراع قيمة أو استعارة دليل.

## تصنيف الوكلاء الفعلي

وجود Edge Function لا يعني أنها وكيل مستقل. الجرد يقسمها إلى أربع طبقات:

| الطبقة | أمثلة | السياسة |
|---|---|---|
| وكلاء ذاتيون مجدولون | تدقيق النظام، توليد الفواتير، تحديث المتعثرين، الإعذار، طلب PDF، ماسحات العقد | هوية آلة + سياسة + قفل تعارض + أثر تدقيق |
| حراس قاعدة مجدولون | صحة العقد، سير العمل القانوني، مطابقة الحكم، إغلاق المراجعات | عمليات محددة، متكررة بأمان، ولا تتجاوز مصدر الحقيقة |
| مراجعون عند الطلب | مراجعة القضية، مطابقة الدفع، مراجعة هوية العميل | يقترحون أو يقررون الجاهزية، ولا يكتبون حقيقة غير مثبتة |
| قدرات أو إصدارات قديمة | `safe-auto-repair` وإصدارات Edge القديمة | معطلة أو غير مجدولة، ولا تُعد كاتباً حياً |

سجل السياسة المركزي يضم العقود، الأسطول، الهوية، المال، القانوني، المراجعات، المخالفات، الإعذارات، طلب المستند، وتقاضي. كل سياسة تحدد `execution_mode`، مستوى الخطر، مجموعة التعارض، الحد الزمني، الثقة الدنيا، وسياسة الدليل.

### لقطة الإنتاج التي بُني عليها القرار

- سجل هوية الاستدعاء يحتوي 9 وكلاء فعّالين؛ وتشغيلات تدقيق النظام خلال 7 أيام: 7 مكتملة و0 فاشلة، وكل المجالات السبعة اكتملت.
- وكيل طلب PDF سجل طلباً واحداً وثلاث عمليات إرسال ناجحة بلا أخطاء مزود وقت المسح.
- تقاضي ما زال نقطة الضعف التشغيلية: 15 مهمة قديمة `needs_human`، ومهمة توقفت عند الاعتماد النهائي، ومهمة فاشلة وقت المسح. نجاح الاختبارات لا يغلق هذه الطوابير تلقائياً.
- يوجد عدد كبير من Edge Functions ذات أسماء إصدارات قديمة؛ هي قدرات منشورة وليست كلها وكلاء مجدولين. مصدر الحقيقة للكاتب الحي هو: سجل الهوية + `cron.job` + عامل سطح المكتب.
- وجد تدقيق الأدلة 183 مستنداً موقعاً بحالة `matched`: 33 فقط تحمل دليلاً دقيقاً قابلاً لإعادة الإثبات، و150 سجلاً قديماً بلا metadata كافية، ومسار تخزين واحد معاد الاستخدام بين عقدين.

بوابة v2 تنفذ القفل فعلياً لكل Edge Function تستخدم `_shared/agent.ts`. أما حراس SQL المجدولون مباشرة فيبقون على أقفالهم/معاملاتهم الخاصة وجدولتهم المتباعدة؛ سجل السياسة يجعلهم ظاهرين، لكن أي تعديل لاحق لجدولهم يجب أن يضيف adapter للقفل قبل اعتباره محكوماً بالنواة نفسها.

## مصفوفة السيناريوهات والقرارات

### 1. التشغيل والجدولة والتعارض

| السيناريو | القرار الآمن | الضابط/الاختبار |
|---|---|---|
| سر الوكيل مفقود أو خاطئ | رفض 401 بلا كتابة | البوابة v1 ثم v2 |
| `agent_id` لا يطابق السر | رفض | سر مستقل لكل وكيل |
| الشركة غير موجودة أو مختلفة | رفض | `company_id` إلزامي ومتطابق |
| الوكيل متوقف أو مفتاح القتل فعال | رفض | `system_agent_controls` |
| الوكيل غير مسجل في السياسة | رفض مغلق | `agent_safety_policies` |
| نفس الطلب أُعيد | السماح لنفس `request_id` فقط بنتيجة متكررة آمنة | مفتاح الطلب + idempotency |
| وكيلان يكتبان نفس المجال | الثاني `busy` | lease حسب الشركة و`conflict_group` |
| انتهت المهلة وبقي القفل | تنظيف القفل ثم استئناف | `expires_at` وحد زمني |
| تعطل الوكيل في منتصف الدفعة | استئناف من المؤشر، لا إعادة كامل الدفعة | cursor/lease/heartbeat |
| إصدار الكرون لا يطابق المصدر | منع النشر وتنبيه | جرد اسم الجدولة/الهدف/الإصدار |
| وكيل قديم عاد بالخطأ | يظل معطلاً | سياسة `retired=true`, `enabled=false` |
| تشغيل يدوي وتلقائي متزامنان | نفس قفل التعارض | لا مسار جانبي خارج البوابة |
| تجاوز عدد التغييرات المسموح في تشغيل واحد | إيقاف التشغيل ورفع تنبيه | `max_mutations_per_run` + سجل before/after |
| تدقيق يولّد آلاف النتائج الشاذة | إيقاف التشغيل عند السقف ورفع تنبيه تشغيلي | `max_findings_per_run` + قفل ذري لكل run |

### 2. العقد والمستند والهوية

| السيناريو | القرار الآمن | الضابط/الاختبار |
|---|---|---|
| لا توجد نسخة عقد | إنشاء طلب PDF وإرساله مرة واحدة لكل مستلم | `missing-contract-pdf-agent` + dedupe |
| ملف على نفس اللوحة لعميل آخر | رفض وتسجيل mismatch | لا مطابقة باللوحة وحدها |
| ملف مرتبط بعقد مختلف | رفض | `contract_id` غير قابل للنقل بعد الرفع |
| نفس `file_path` مستخدم لعقدين | رفض قيد قاعدة البيانات | `SIGNED_CONTRACT_FILE_REUSED_ACROSS_CONTRACTS` |
| PDF بلا ملف فعلي | رفض الجاهزية | `file_path` إلزامي |
| OCR لا يقرأ النص | `failed` وطلب نسخة أوضح | لا تخمين |
| الاسم مطابق تماماً | يمكن `matched` | تطبيع عربي ثم مساواة كاملة |
| الرقم الشخصي مطابق تماماً | يمكن `matched` | أرقام مطبّعة ومساواة كاملة |
| الاسم متقارب جزئياً فقط | `unverified` | لا ترقية بالتشابه الجزئي |
| الاسم يطابق والرقم يخالف | `mismatch` | تعارض الرقم أقوى من الاسم |
| اسم المستأجر والعميل مختلفان | `mismatch` | إيقاف القانوني والمالي المعتمد على المستند |
| الحالة `pending` | تمر إلى ماسح الهوية فقط | لا تستخدم كدليل قانوني |
| الحالة `unverified` أو `failed` | طلب معالجة/نسخة جديدة | لا رفع دعوى ولا استخراج مالي |
| وثيقتان matched فعالتان لنفس العقد | إيقاف الجاهزية حتى تعيين واحدة `active` والبقية `superseded` | لا اختيار صامت للأحدث |
| سجل قديم `matched` بلا تفاصيل إثبات | لا إبطال جماعي؛ إعادة مسح مرحلية قبل أي انتقال حرج | backfill/rescan متدرج |
| alias موثق لنفس العميل والعقد التجاري | يُقبل فقط عبر رابط canonical مؤكد بكل مفاتيحه | لا نسخ الملف ولا تغيير `contract_id` |
| محاولة تغيير هوية مستند matched | إعادة تحقق كاملة أو رفض | trigger على حقول الهوية |
| رفع موظف لملف جديد | يبدأ `pending` | لا ثقة بسبب دور الرافع |

### 3. العقد والأسطول

| السيناريو | القرار الآمن | الضابط/الاختبار |
|---|---|---|
| عقد نشط وله مركبة صحيحة | المركبة مستأجرة | رابط مباشر + حالة العقد |
| عقد تحت إجراء قانوني | تبقى مستأجرة ما لم توجد عودة مثبتة | الحالة القانونية شاغل فعلي |
| لا يوجد عقد شاغل | متاحة إذا لا يوجد مانع آخر | بحث كل الإشغالات النشطة |
| عقد نشط بلا مركبة | finding عالي، لا تخمين مركبة | review-only |
| مركبة عليها عقدان نشطان | منع التفعيل الثاني | قيد/بوابة ذرية |
| لوحة المستند لا تطابق المركبة | `mismatch` | اللوحة إشارة تحقق لا مفتاح ربط |
| عقد ملغى أو منتهٍ مع تسليم مثبت | تحرير المركبة | انتقال ذري بعلة |
| عقد منتهٍ بلا تسليم | لا تجعلها متاحة تلقائياً | مراجعة إشغال |
| مركبة مسروقة/محجوزة/صيانة | لا تجعلها متاحة | أولوية حالات المنع |
| حالتا عقد ومركبة تتغيران معاً | معاملة واحدة + postcondition | لا تحديثين منفصلين |
| تشغيل موزع العقود أثناء حارس الصحة | واحد فقط يكتب | `contract_assignment`/`contract_health` leases |
| لوحة بصيغ مختلفة | تطبيع قبل المقارنة | أرقام عربية/مسافات/رموز |

| السيناريو | القرار الآمن | الضابط/الاختبار |
|---|---|---|
| فاتورة بلا عقد | مراجعة أو إصلاح من علاقة مثبتة فقط | لا اختيار أقرب عقد |
| دفعة بلا تخصيص | تبقى advance/unallocated | لا تعتبر فاتورة مدفوعة |
| دفعة مرتبطة بعقد عميل آخر | رفض الربط وفك المقترح | نفس الشركة والعميل والعقد |
| دفعة مرتبطة بفاتورة عقد آخر | رفض | تحقق الرسم كاملًا |
| تخصيص يتجاوز المتبقي | رفض ذري | invariant المبلغ |
| دفعة مكررة | dedupe بالمصدر/المرجع/المبلغ/التاريخ | مفتاح idempotency |
| فاتورة ملغاة | لا تخصيص جديد | تحقق lifecycle |
| قيد غير متوازن | رفض المعاملة | مجموع المدين = الدائن وخطان فأكثر |
| حساب رئيسي | رفض الترحيل | `is_header=false`, level>=3 |
| مبلغ صفر أو سالب | رفض | validation قبل الكتابة |
| تاريخ استحقاق فاتورة عقد | أول شهر الفاتورة نفسها | قاعدة prepaid DB-wide |
| مصالحة وفيها دفعات غير مخصصة | لا تعيد بناء الرسم تلقائياً | تحل التخصيص أولاً |
| تغير الرصيد بعد قراءة الوكيل | إعادة قراءة داخل المعاملة | live snapshot + lock |
| فشل بعد إنشاء فاتورة وقبل القيد | rollback كامل | معاملة واحدة |
| اختلاف شروط PDF والبيانات | اقتراح مراجعة، لا auto-apply | مستند matched + ثقة + اقتباس |

## التغييرات المنفذة في الفرع المحلي

1. بوابة استدعاء v2 تستدعي تحقق الهوية الحالي ثم تفرض السياسة وقفل التعارض وتسجل القرار.
2. حارسان على `contract_documents`: ثبات ربط العقد، منع إعادة استخدام ملف التخزين، ومنع `matched` إلا بهوية دقيقة.
3. اختيار مستند الدعوى لا يقبل إلا `matched`؛ ويُرسل `pending` وحده إلى ماسح الهوية.
4. تشابه الاسم الجزئي أصبح `unverified` بدلاً من `matched`.
5. مراجع القضية وماسح الشروط لا يقبلان مستنداً غير matched.
6. وكيل طلب النسخة يبقى المسار التلقائي عند النقص، وليس استعارة ملف.
7. سجل جرد موحد يعرض السياسة، التسجيل، الكرون، والقفل الحي.
8. rollback مطابق لا يحذف مستندات أو عقود أو قيوداً مالية.

## ترحيل آمن للبيانات القديمة

المسح الحي وجد عدداً كبيراً من سجلات `matched` القديمة التي لا تملك تفاصيل تحقق دقيقة، ووجد مسار تخزين واحداً معاد الاستخدام بين عقدين. لا يجوز تحويل كل القديم إلى mismatch دفعة واحدة لأن ذلك قد يوقف ملفات صحيحة.

الترحيل المقترح:

1. منع الأخطاء الجديدة أولاً بالـ triggers.
2. عزل الملف المعاد استخدامه المعروف وطلب النسخة الصحيحة.
3. إعادة مسح السجلات القديمة على دفعات، مع أولوية العقود القانونية والنشطة.
4. لا تُستخدم السجلات القديمة في انتقال قانوني/مالي جديد حتى تجتاز إعادة التحقق.
5. قياس blocked/failed/busy ونسبة false positive قبل توسيع auto-apply.

## بوابات القبول قبل الإنتاج
