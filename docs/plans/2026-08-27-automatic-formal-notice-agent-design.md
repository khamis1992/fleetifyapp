# تصميم وكيل الإعذار الرسمي التلقائي — 2026-08-27

## القرار

يعمل الوكيل تلقائياً دون اعتماد بشري عندما يبلغ أقدم استحقاق غير مسدد عشرة
أيام. لا يعيد استخدام `reminder_history` كإعذار؛ بل ينشئ دورة مستقلة تحفظ
الرصيد الحي، نص الإعذار، رقم الهاتف، رقم رسالة المزود، وبصمة المحتوى.

## دورة العمل

1. يشغّل `pg_cron` الوكيل يومياً بهوية مستقلة محفوظة في Vault.
2. يجمع الوكيل الفواتير المتأخرة المرتبطة بعقد وعميل ذي رقم هاتف صالح،
   بحد أقصى 25 إعذاراً في التشغيل اليومي.
3. يمنع مفتاح `contract + notice type + oldest overdue month` تكرار الإعذار
   لنفس دورة التعثر.
4. يحسب الوكيل الرصيد من سجل تخصيص الدفعات الحي قبل الإرسال مباشرة، ثم
   يرسل مطالبة سداد محددة
   بالعقد والفواتير والمبلغ ومهلة سبعة أيام وطلب إقرار بالاستلام.
5. يحفظ نجاح قبول الرسالة من Ultramsg كحالة `sent` فقط، وينشئ إشعاراً
   رسمياً غير مؤكد الوصول.
6. يستقبل webhook حالات `delivered/read`. عندها ينشئ ملف JSON غير قابل
   للاستبدال في حاوية `contract-documents`، مقتصراً على بصمة الرسالة وبيانات
   المزود التقنية دون اسم أو هاتف أو مبلغ بسبب الوضع العام للحاوية القديمة،
   بينما تبقى الرسالة والحدث الخام داخل جدول محمي بـRLS. ثم يربطه بسجل
   `legal_case_formal_notices` ويثبت تاريخ الوصول.
7. لا تعتبر شاشة تجهيز الدعوى الإعذار مكتملًا إلا بعد وجود
   `delivered_on + proof_document_id`، وفق الحارس الحالي.

## حدود الأمان

- لا إرسال دون عقد، عميل، هاتف، فواتير مستحقة ورصيد موجب.
- لا إرسال عند وجود دفعة مكتملة غير مخصصة للعميل/العقد أو تخصيص عام للعقد؛
  يؤجل الوكيل الإعذار حتى يحسم النظام المالي أثرها على الفواتير.
- لا إعادة إرسال لنفس دورة التعثر، ولا تعديل لنص أُرسل.
- لا تسجل حالة الوصول من مجرد قبول API؛ يلزم webhook يحمل رقم الرسالة.
- لا يستبدل الوكيل webhook آخر مهيأ لدى Ultramsg. يسجل فشل إعداد واضحاً.
- جدول الوظائف للقراءة فقط لأعضاء الشركة؛ الكتابة للـservice role فقط.
- أسرار الجدولة والـwebhook تبقى في Vault ولا تخزن في السجلات أو الواجهة.
- الرد أو القراءة يقويان الدليل، لكن تقدير الحجية القانونية يبقى للمحكمة.

## التحقق

- اختبارات ثابتة للمخطط، الهوية، الجدولة، منع التكرار، الفصل بين الإرسال
  والوصول، وحفظ مستند الإثبات.
- اختبارات وحدات لاستخراج webhook وتوليد نص الإعذار.
- فحص TypeScript وESLint ومستشاري أمان/أداء Supabase.
- بعد النشر: التحقق من وجود cron واحد، وهوية واحدة، ووظائف Edge المنشورة.
