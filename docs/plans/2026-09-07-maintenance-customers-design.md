# إعادة تصميم الصيانة والعملاء وعلاقات العملاء

النطاق هو الصفحات الثلاث المطلوبة ونوافذها وإجراءات العرض والتنقل. العربية وRTL هما الأساس. الهوية تتناسق مع القسم القانوني: أرضية عاجية، بترولي للصيانة وأخضر داكن للعملاء، ولمسات نحاسية للأولوية. خط Cairo الحالي. لا تغيير لصلاحيات المستخدم أو المعالجات المالية أو بيانات السجلات.

التصميم: رأس واضح بإجراء أساسي، تنقل بين الصفحات ذات الصلة، شريط مؤشرات بمصدر واضح، بحث وفلاتر مستقلة عن العنوان. الصيانة تضع المركبات والطلبات أمام الملخصات؛ دليل العملاء يعرض بطاقات هوية واتصال وإجراءات واضحة؛ CRM ينظم قائمة المتابعة بجانب المواعيد المجدولة، مع جدول وبطاقات للهاتف.

- [x] الغلاف المشترك والألوان والنوافذ وحالات التحميل والخطأ.
- [x] الصيانة: لوحة جديدة، سجل وفلاتر مباشرة، تصدير حقيقي، ووضوح نطاق آخر 100 طلب.
- [x] العملاء: البطاقات والبحث وأدوات الاستيراد والتصدير والعرض المقسم.
- [x] CRM: أولويات المتابعة والجدول والبطاقات ونوافذ الملاحظات والتقارير.
- [x] اختبار المتصفح والهواتف، اختبارات التغييرات الوظيفية، TypeScript والبناء.

لا نشر ولا معاملات فعلية أثناء الاختبار. التعديلات السابقة في مساحة العمل محفوظة.

## التنفيذ والتحقق

الغلاف في `src/components/operations/OperationsWorkspace.tsx` وتنسيقاته محصورة بالصفحات الثلاث والنوافذ المفتوحة منها. تُحذف علامة تنسيق النوافذ عند مغادرة الصفحة. استُخدمت أسماء أصناف وعلامات DOM صريحة حتى تحتفظ أداة تنقية CSS بها في الإنتاج.

أصبحت فلاتر الصيانة والتنقل بين صفحات السجل مباشرة، مع إعادة الصفحة إلى الأولى بعد تغيير البحث. تصدير CSV فعلي للنتائج المحمّلة المطابقة للفلاتر، ويحفظ النص العربي والقيم الصفرية ويحمي حقول النص من صيغ الجداول. تم الحفاظ على تأكيد العمليات التي تغير حالة الصيانة أو تلغي الطلب.

العرض المقسم يعرض الاسمين العربيين أولًا ويتحول إلى قائمة وتفاصيل متتالية على الهاتف. عناوين ملخصه توضّح أن العقود هي آخر خمسة معروضة، وأن الدفعات غير المكتملة ليست رصيد المديونية. لم تتغير معادلات أو استعلامات الدفعات.

التحقق:

- `npm run type-check`: ناجح.
- `npm run build:ci`: ناجح، مع تحذيرات حجم الحزم والاستيرادات المشتركة الموجودة في المشروع.
- 12 اختبارًا ناجحًا في ثلاثة ملفات: غلاف الواجهات والتصدير والتنقل، تفاعلات سجل الصيانة، واختبارات ملف العميل السابقة.
- ESLint للملفات المعدلة: لا أخطاء؛ بقيت تحذيرات في الأجزاء القديمة، مثل الأنواع `any` والاستيرادات القديمة. المكونات والمساعدات والاختبارات الجديدة دون تحذيرات.
- تم تمرير CSS الجديد عبر إعداد PostCSS الخاص بالإنتاج والتحقق من بقاء نطاق النوافذ ولون الصيانة وارتفاع النوافذ المناسب للمحتوى.
- معاينة فعلية للصفحات الثلاث بالحجم المعتاد وبعرض هاتف 390 بكسل. عرض مستند الهاتف 375 بكسل بعد شريط التمرير، دون تجاوز أفقي للصفحات الثلاث.
- فتح سجل الصيانة والبحث فيه وفتح تفاصيله، ومعاينة نموذج إنشاء الصيانة ثم إلغائه؛ معاينة بطاقات العملاء وقائمة الإجراءات والعرض المقسم واختيار عميل ونموذج الإضافة ثم إغلاقه؛ تبديل CRM إلى البطاقات وفتح نافذة ملاحظة وإلغائها.
- أُعيد حجم المتصفح إلى الوضع الافتراضي. لم تُرسل رسائل ولم تُحفظ بيانات اختبار في النظام.

نطاق التصدير المعروض في الصيانة هو آخر 100 طلب محمّل فقط، وليس أرشيف الصيانة الكامل. تصدير وتقارير CRM والاستيراد ونماذج الحفظ تحتفظ بمعالجاتها الحالية؛ الاختبار الحي اقتصر على العرض والتنقل والنوافذ، دون تنفيذ تغييرات على السجلات.
